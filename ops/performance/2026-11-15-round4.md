## Backend queries, cache reads and allocations

Fresh-process diagnostics compare frozen source from
`/tmp/pacestats-round4-baseline` with the candidate. The measurements below are
individual local samples, not statistical medians. Node process CPU does not
include MySQL server CPU. Decoded SQL result bytes are a JSON-size proxy, not
MySQL wire bytes, and heap deltas depend on garbage collection.

| Workload | Before → after |
|---|---|
| Recover missing compact main board from generated root | 90 → 6 RedisJSON reads; 25.6 → 7.7ms; identical board values and order |
| Ten-row AA presentation | 345,511 → 74,322 Redis response bytes; 4.2 → 2.6ms; eight limit/fastest variants match the complete board |
| Session overflow query, actual `EXPLAIN ANALYZE` | Materialize/count 10,001 rows → one sentinel result; 5.19 → 3.94ms |
| One lifetime split, 21,593 runs | 15 → 2 columns; 6,024,116 → 765,707 decoded bytes; Node CPU 45.1 → 13.2ms |
| Legacy complete split and nether windows | Two reads per source → one; each retains the existing 21,593-row result in this fixture |
| Ten profiles with fewer than 25 runs | 20 → 10 SQL reads; 9.4 → 7.0ms; no separate count scans |
| 50,000 defined-value local-cache hits | 50,000 → zero extra `has` checks; CPU 58.6 → 38.4ms; elapsed 35.6 → 28.6ms |
| Eighteen serial scoped fallbacks with injected 10ms Redis failures | 18 → 1 failing Redis commands; 204.6 → 25.1ms; successful recovery after the one-second retry interval |
| 100 player-name API requests, 4,350 users | 100 → 1 name projections; CPU 85.6 → 80.5ms; source replacement invalidates the projection |
| Invalid/cold lookup limits | Eight invalid requests perform zero SQL/Redis reads; eight distinct Mojang lookups may remain active, the ninth receives 429, and recovery succeeds |

The batched main-board fixture transfers slightly more data, 452,950 → 455,128
bytes, because the multi-path responses include their path keys. Its benefit
is fewer round trips, not lower response size. The overflow sentinel still
walks the bounded index prefix; it removes the temporary materialization and
aggregate rather than claiming an O(1) index seek.

Short-page inference retains exact totals for first and partial final pages.
An empty out-of-range page still obtains the real count. A full page now waits
for its row read before starting an uncached count. The cold concurrent burst
below exposes an observed full-page latency regression from that sequencing
tradeoff, while short results avoid the count scan entirely.
The imported dataset has 1,033 of 4,350 players with fewer than 25 runs; this
is a dataset observation, not a claim about request popularity.

Cache-key regression checks retain argument boundaries, object-key ordering,
interval normalization, undefined/null distinctions, nonfinite numbers,
BigInts and dates. An undefined cached result remains a hit. Failed fetches
still retry, apart from the explicit compact-user Redis retry interval.
The cache-hit heap sample increased, 6.1 → 8.3MiB; it does not demonstrate a
lower measured heap despite removing intermediate allocations and lookups.

The Redis failure interval applies only to compact-user read failures and is
at most one second. It does not put an empty user list or failed result into
the ordinary 60-second success cache. SQL fallbacks stay scoped and recovery
is tested. `forceName` now parses its documented boolean: `false` permits
Twitch aliases, while `true` retains nickname-only lookup and its 401 result.
Mojang UUID input is validated, including accepted compact and hyphenated forms.
Rate and concurrency limits are process-local, not distributed quotas.

## Websocket work distribution

Three diagnostic pairs with 20,000 pending UUIDs reduce active timers from
20,000 to one. Their median Node CPU is 26.9 → 19.6ms and retained heap is
about 7.34 → 2.65MiB. This stress test checks scheduling/allocation overhead,
not a measured 20,000-client production network workload.

Delivery regressions preserve duplicate coalescing, reload priority,
first-event deadlines, reentrant additions and shutdown cleanup. Weighted
dispatch now yields between due groups. A fixture with 100 groups of 100
subscribers sends at most two such groups per callback under the default
256-weight budget. One UUID group remains atomic and can itself exceed that
budget, so it is not a hard cap on callback CPU or recipients.

The heartbeat fixture covers 10,000 clients: a previous all-client callback
becomes batches of at most 256 pings, each client is pinged once per cycle,
missing pong responses terminate on the next cycle, and idle/close/shutdown
cleanup leaves zero timers. This spreads work and permits intervening I/O;
it does not prove that all websocket CPU spikes are removed.
